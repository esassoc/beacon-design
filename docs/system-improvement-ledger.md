# System Improvement Ledger — beacon-design

Spoke friction that turned out to be the system's fault, one line each: what was
missing, where it bit, the proposed hub fix. Reviewed for promotion to the hub.

- 2026-07-15 — **manifest cross-check can't see PascalCase spoke components**: `scripts/lib/manifest-crosscheck.mjs` `importToKebab()` lowercases the import basename (`BcnProjectHeader` → `bcnprojectheader`), which can never match a kebab manifest resolver (`bcn-project-header`), so every manifest'd page in this spoke throws false `manifest-declared-absent` errors (bit on `project-dashboard.astro` — 6 false errors in /design-qa). Proposed hub fix: `return pascalToKebab(base)` at `manifest-crosscheck.mjs:52` (a no-op for the hub's already-kebab basenames).
- 2026-07-15 — **check-adherence token scan reads `var(--…)` inside comments**: PageLayout.astro's frontmatter doc comment (`$gray-N → var(--bcn-gray-N)`) produced two false `token-undefined` errors. Worked around by rewording the comment. Proposed hub fix: strip comments before the token scan.
- 2026-07-15 — **composition-heft heuristic fires on section components**: the >120-style-line "page is hand-rolling" warning (documented as per-authored-PAGE) flagged `BcnStarredComponents` / `BcnTrackingZone`, which are section components that legitimately own their CSS. Proposed hub fix: apply the heuristic only to files under `src/pages/`.
- 2026-07-15 — **no neutral count-badge variant in `esa-badge`**: six saturated-fill variants, no border option, green `primary` as default — Andy wants a neutral gray-border count as the system DEFAULT and the green excised. Bit on project-dashboard (composed in-spoke as `BcnCount` meanwhile). Tracked as margot thread `thr-mrmjb7v7-1f211c7b`. Proposed hub fix: add the neutral variant, make it the count default.
- 2026-07-15 — **RESOLVED hub-side**: the manifest cross-check PascalCase gap above is fixed in ecology `c47d3de` (`importToKebab` now kebabs basenames), together with a second false positive found the same way: web-component side-effect imports in body `<script>` blocks (the only place they can live — frontmatter would execute the element during SSR) now count as composition imports. Both pinned with tests. Bit again on `fish-gantt.astro` + reproduced on shipped `permit-tracking.astro` (6 false errors) before fixing.
- 2026-07-15 — **banned-border-left rule fires on chart lines**: `check-adherence` flags Gantt gridlines, milestone dashes, and the today-line — zero-width `border-left` elements inside the plot — as "colored left-border status indicators," which they aren't (the ban targets status/category edges on cards/rows/containers). Bit on `fish-gantt` (`BcnWorkBreakdown`, `BcnRollupSummary` — 5 false errors). Worked around by drawing the lines as `width:1-2px; background` / `box-shadow` / `repeating-linear-gradient`. Proposed hub fix: exempt `width: 0`/line-shaped elements, or scope the rule to selectors that also carry card/row/container classes.
- 2026-07-15 — **decomposition-context.mjs returns an empty `spokeInventory` in a git worktree**: running the grounding script from the `beacon-design--ws-fish` worktree produced 0 spoke components, so `reuseHints` was blank and the decomposition reviewer had to do its reuse comparison by reading files directly. Proposed hub fix: make the inventory scan worktree-safe (likely resolving paths through `.git` file indirection or the repo scan root).
- 2026-07-15 — **no size variant on `esa-stat`**: the Study Planning KPI strip needed a compact stat; page-side `:global` overrides shrink value/label/sub. Proposed hub fix: `size="sm"` prop on esa-stat.
- 2026-07-15 — **the served token sheet dropped the legacy named ramps**: `@esa/tokens`'s package export maps `tokens.css` → `dist/tokens.css`, which ships Radix-style ramps (`--color-green-1..12`) but NOT the legacy names (`--color-green-700`, `--color-orange-500`, `--color-blue-500/700`) that `theme-beacon.css`'s re-points were written against — so `--color-success`, `--color-warning`, `--color-ai`, `--color-ai-hover` resolved to NOTHING at runtime (on-track/attention pulse dots rendered transparent; Andy caught it as "why do some TMR have dots and others don't"). Worked around by inlining the four values in the theme. Proposed hub fix: either ship the legacy named ramps in `dist/tokens.css` or add a build-time check that every spoke-theme `var()` target exists in the served sheet (check-adherence's vocab scan reads the whole package tree, so it missed this — it should read ONLY the sheets the export map actually serves).
- 2026-07-16 — **owner-override pragma added to check-adherence**: `adherence-allow: font-too-small` same-line comment suppresses the type-floor rules where Andy explicitly sanctions an exception (ecology commit; first use: fish-gantt 11px ID badges). Consider extending the pragma to other rules as sanctioned cases arise.
- 2026-07-16 — **unitless `--side-dialog-inset` silently kills esa-side-dialog's width**: the panel width is `min(var(--_width), calc(100vw - var(--_inset) * 2))`; a unitless `0` is a `<number>` in a length calc → invalid at computed-value time → `width: auto` → the panel grows to fit content (bit on BcnGuidanceDrawer: drawer blew to full viewport when an article expanded; no console error, pure silent failure). Proposed hub fix: document "inset must carry a unit," or guard in the lego (e.g. interpret the var through a registered `@property <length>`).
- 2026-07-16 — **esa-icon scale floors at 14px**: BcnAldoMark's 20px `sm` badge needs a 12px glyph; only reachable by overriding the lego's internal `--icon-size-xs` token from the host. Proposed hub fix: a 12px `xxs` step (or honor an explicit pixel `size`).
- 2026-07-16 — **esa-icon-button can't take custom Lucide `paths`**: forwards only registry icon names — the same gap AppShell:261 documents; bit again on the help bar ('sparkles' isn't in the registry → shipped 'star'). Proposed hub fix: forward a `paths` prop to the inner esa-icon (and/or grow the registry: sparkles, compass, list, book, message-circle all missed this session).
- 2026-07-16 — **esa-card's `icon` prop draws a hardcoded info glyph**: the prop accepts a name but renders the info path regardless, so a card can't carry its own leading icon (bit on BcnKbCategories — tiles went owned-anchor instead; esa-card also being a `<div>` blocks linked-tile semantics). Proposed hub fix: honor the name (+ a `href` linked-card mode).
- 2026-07-16 — **esa-sidebar-nav fights content surfaces three ways**: its group heading IS the banned ornamental micro-label (11px uppercase letter-spaced, esa-sidebar-nav.ts:318-324 — the hub lego violates design-principles); per-item hint renders only as a filled badge pill (no quiet text mode); and its shadow DOM blocks light-DOM search/`<mark>` highlight (bit on BcnKbBrowser — rail went owned). Proposed hub fix: normal-case heading per the design principles, a text-hint mode, and/or a light-DOM nav variant.
- 2026-07-16 — **esa-collapsible can't carry a summary sub-line**: title-string-only API — no slot for the one-line description under the title that list rows need (bit on the guidance drawer's article rows; became native `<details>`, later dropped for the stacked-reader model anyway). Proposed hub fix: optional `description` + a slotted summary.
- 2026-07-16 — **no esa- chat composer**: second spoke to hand-roll one (auto-grow textarea + embedded send). esa-textarea can't render bare (owns its border/focus), has no trailing-action slot, and its auto-resize clips at max instead of inner-scrolling (bit on the drawer's Ask Aldo composer). Proposed hub fix: `esa-composer`, or a "bare/embeddable" esa-textarea mode + trailing-action slot + inner-scroll resize.
- 2026-07-16 — **esa-side-dialog stacking + scroll access are convention, not API**: the card-stack works by re-pointing the parent's `--side-dialog-inset` (documented in a CSS comment) and scroll control requires reaching into the open shadow root's `.body` (bit on the drawer's stacked article reader + chat auto-scroll). Proposed hub fix: a first-class `stacked` prop and a `shown` event / scroll method.
- 2026-07-16 — **POSITIVE exemplar — esa-icon-button themed to a dark zone by construction**: the help bar's dark-glass treatment needed zero overrides — `--icon-button-bg-hover` hook + glyph AND focus ring drawn from `currentColor` meant setting zone color was enough. The theming-hook pattern done right; hold new legos to it.
- 2026-08-05 — **no esa- chart lego, third occurrence**: the Compliance Oversight Dashboard needed a clickable severity donut (`BcnOversightHero`) and a weekly opened/resolved bar chart (`BcnTrendPanel`), both bespoke SVG/CSS — same gap already logged against `BcnMonitoringStats`' donut/bars and `permit-tracking.astro`'s exec-hero-band donut. The new donut had to be built as stacked `<circle>` strokes specifically because a flat `conic-gradient` (the existing idiom) can't carry a per-segment click target. Proposed hub fix: `esa-donut-chart` (segments `{label,value,hex,href?}`, center slot, legend, optional per-segment link) and a small `esa-bar-series`/`esa-sparkline` (shared-max scaling, legend, accessible table fallback) — both would retire several spoke-local re-implementations of the same viz.
- 2026-08-05 — **no esa- map lego, third occurrence**: `BcnObservationMap` (severity-pinned Leaflet map, reused as a dashboard inset and a full interactive list-page map) is the third hand-rolled Leaflet surface in this spoke (`BcnProjectMap`, `site-clearance.astro`'s work-area/observation map, now this one), each re-deriving basemap setup, inset-vs-interactive option sets, and token→literal color resolution for markers. Proposed hub fix: a parameterized `esa-map` (points/geojson props, height, interactive flag, a pin-click event) — `BcnObservationMap`'s multi-instance-safe, DOM-data-attribute-threaded pattern is a reasonable starting shape for it.
- 2026-08-06 — **`esa-card` accepts no host class or id**: it composes its class list from variant props only (`variant` / `headerVariant` / `padding`), with no passthrough, so a page cannot address one card among several. Bit while writing handoff specs for the Compliance Dashboard, whose three sections are each a whole `esa-card`: the only way to target them is `.esa-card:has(.bcn-ohero)` — a `:has()` on a child the card knows nothing about, which silently breaks the moment that child is renamed. Same gap would block any page-level style hook, analytics attribute, or scroll anchor on a card. Proposed hub fix: forward `class` and `id` (and ideally `...rest`) to the root `<div>`, which is what the other `.astro` legos already do.
- 2026-08-06 — **coverage-based CSS selection makes handoff bundles non-reproducible**: the hub's "Chrome rule-usage coverage for used CSS" technique makes a bundle's contents a function of what the renderer happened to exercise inside a fixed `waitForTimeout(200)` window, not of the page. Measured: regenerating ONE unchanged route twice back-to-back on the same machine produced different bytes, and a full run rewrote ~95 files nobody had touched — which is how a routine `git pull` became a 101-file conflict, and why a slower machine disagreed with a faster one on the same commit. Two causes: rule ORDER (`CSS.stopRuleUsageTracking` returns first-USE order, paint-timing dependent) and rule SET MEMBERSHIP (what finished rendering inside the sleep). Sorting fixed the first; nothing fixes the second while coverage is the selector — `fonts.ready` + double-rAF was tried and measured and did not converge. **Fixed spoke-side in `scripts/lib/capture-curated.mjs` by dropping the coverage pass entirely**: all stylesheet rules are enumerated (sheets ordered by a content-derived key, rules keeping source order within a sheet, which is the cascade's own tiebreak) and narrowed by the class-partition filter that already existed downstream — a pure function of the markup. Verified byte-identical across repeated full runs; bundle size grew 2% (176→180 KB on `release-notes`), and `:hover`/`:focus` rules the renderer never exercised are now captured, which a handoff artifact wants. **The hub's own `@esa/handoff/src/capture.mjs` still has the original bug**, and the 24 spoke routes with no curated spec fall through to it: measured after the spoke fix, 0 of 11 curated bundles vary between runs and 24 of 24 fallback bundles still do. Proposed hub fix: the same change in `capture.mjs`. Until then, writing a curated spec for a route is also what makes it reproducible — the guidance gate (`npm run handoff:check`) pushes that direction anyway.
- 2026-08-05 — **icon registry missing common action glyphs**: `BcnAttentionPanel`'s spreadsheet/KMZ export buttons wanted `download` and `map` icons; neither exists in `@esa/ecology`'s icon registry (confirmed list: arrow-\* chef-hat chevron-\*/chevrons-\* circle-\* credit-card external-link file-text layout-dashboard map-pin notepad-text rotate-ccw trash-2 trending-up triangle-alert), and `EsaButton` doesn't forward a `paths` override to `EsaIcon` as a workaround — an unknown name silently renders a blank 20px SVG. Worked around with `arrow-down`/`map-pin`, which read slightly off-label. Same class of gap already logged against `esa-icon-button`'s registry-only `paths` forwarding. Proposed hub fix: add `download`, `map`, `file-spreadsheet`, `upload` to the shared registry, and/or let `EsaButton` forward `iconPaths` through to `EsaIcon` like the mid-tier legos already do.
- 2026-08-17 — **check-adherence's `hand-rolled-primitive` scan reads code inside COMMENTS**: `<input type=color>` written inside a `bcn-lego-checked` justification comment (BcnLogoPicker.astro:38 — prose explaining why esa-color-picker's internals don't fit a keyed swatch set) is reported as an **ERROR**, i.e. the Must-fix class, on a file that hand-rolls no input at all. Same family as the 2026-07-15 entry above, which was fixed for the TOKEN scan only — comments are still live text for the primitive scan. It punishes exactly the behavior the escape hatch asks for: naming the lego you rejected and why. Proposed hub fix: strip comments once, up front, for ALL scans rather than per-rule.
- 2026-08-17 — **check-adherence's `hardcoded-color` can't see a `var()` fallback nested inside a color function, and directly contradicts `private-no-fallback`**: the rule's own message says "bare hardcoded color (not a var() fallback)", but `color-mix(in srgb, var(--_tone, #bdbdbd) 16%, transparent)` is flagged (BcnComponentGrid.astro:411-412, BcnWorkAreaBoard.astro:492-493). The literal IS a var() fallback; the matcher just doesn't recurse through `color-mix()`. Worse, the two rules are mutually exclusive on the same line — adding the literal fallback that `private-no-fallback` demands is what creates `hardcoded-color`. Measured on this branch: satisfying the first traded 10 warnings for 6. The hub's own legos use the flagged idiom (`esa-badge.astro:23` — `var(--badge-bg, var(--color-primary, #43608a))`), so spoke code following hub practice cannot come out clean. Proposed hub fix: parse `var()` fallbacks recursively through color functions, and make the two rules aware of each other.
- 2026-08-17 — **`esa-badge`'s public token hooks are DEAD as soon as a variant is set**: `--badge-bg` / `--badge-text-color` are honored only on the base rule (`esa-badge.astro:23-24`); every variant class re-points the private `--_badge-bg` / `--_badge-text` directly (`:51-55`, and `:65-70` for dot mode), which wins. A theme or host that sets `--badge-bg` sees nothing happen the moment `variant` is non-default — silently, no console warning. Bit on the component-dashboard status badges: the override appeared to apply and did not, and the workaround was setting `background`/`color` directly, which defeats the entire token layer. Proposed hub fix: have variant classes set the PUBLIC tokens, or route variants through a single `--_badge-bg: var(--badge-bg, var(--_variant-bg))` chain so a host override always wins.
- 2026-08-17 — **`esa-select`'s `value` is an accessor, not a reactive property, so a server-rendered `value` attribute is silently inert**: `value` is absent from `static properties` (`esa-select.ts:26-43`) and exists only as a getter/setter pair (`:100/106`), so Lit never observes the attribute. SSR'd markup carrying `value="…"` renders the placeholder instead, with no warning. Bit on the work-area import mapping (pre-selected column guesses vanished on hydration); worked around by threading the value through `data-*` and applying it from JS after registration. Applies to any `.astro` page rendering a `.ts` lego with a value. Proposed hub fix: add `value: { type: String }` to `static properties`, or document attribute-vs-property per lego in the catalog — this is a whole CLASS of gotcha for a compile-time-templating spoke.
- 2026-08-17 — **`esa-icon-button` has a closed prop set and silently drops everything else**: `{icon, label, href, size, type}` only (`esa-icon-button.astro:15-25`), no `class`/`id`/rest passthrough, unlike `esa-button`. Every `id`, `data-*` and `aria-pressed` hook has to ride a wrapper `<span>` — and the click listener with it. Bit repeatedly on the component header (star, logo-edit) and the map expand control. SAME gap already logged against `esa-card` on 2026-08-06: it is a family, not a one-off. Proposed hub fix: forward `class`, `id` and `...rest` to the root element across the presentational `.astro` legos, as most already do.
- 2026-08-17 — **the `.sidebar` primitive is a WRAPPING flex row, which silently defeats inner scroll containers**: `display: flex; flex-wrap: wrap` (`@esa/tokens/src/layouts.css:81-88`). A wrapped flex line's cross-size is content-driven, so a child can never be bounded by the container's height, and any `overflow:auto` pane inside it grows instead of scrolling. Bit on the applicable-commitments drawer: two panes grew to 2,205px inside a 506px shell and the whole drawer scrolled instead of the lists. Correct flex behavior, but the failure is invisible — nothing errors, the layout just quietly stops being scrollable. Replaced with a two-column grid. Proposed hub fix: document the constraint on the primitive ("children cannot be height-bounded — use `.grid` when they must be"), or ship a non-wrapping variant for bounded shells.
- 2026-08-17 — **no `esa-map` lego, FOURTH occurrence**: `BcnComponentMap` (work-area points plus derived footprint polygons, inset-card-with-modal and full-page variants, status-token legend) joins `BcnProjectMap`, `site-clearance.astro`'s map, and `BcnObservationMap` (3rd logged 2026-08-05). It re-derived the same three Leaflet gotchas a fourth time — `setView()` before any layer, lazy creation inside a hidden dialog, and a 0x0 measurement inside a hidden panel (now self-healing via a `ResizeObserver` that re-fits on first real size, which is the pattern the hub should own). `BcnProjectMap` was unreusable specifically because it hardcodes singleton DOM ids; `BcnComponentMap`'s required `idPrefix` plus DOM-threaded JSON payload is the multi-instance shape a real lego needs. Proposed hub fix: a parameterized `esa-map` (points + polygons/geojson, height, interactive flag, legend, tooltip/click events, required id prefix) with the hidden-container refit built in.
- 2026-08-17 — **Astro serializes `false` boolean attributes onto CUSTOM elements, and Lit reads presence as true**: `checked={false}` on a Lit lego emits `checked="false"`, which Lit's boolean converter treats as SET — so every toggle rendered "off" from data came up ON. Not a lego bug and not an Astro bug in isolation; it is the seam between a compile-time templating layer and a runtime custom-element layer, and it fails silently in the direction that looks like working UI. Bit on the component data panel's layer switches, and a latent instance was found in `BcnProjectDataPanel` the same day. Fix is `checked={value || undefined}` everywhere. Proposed hub fix: document this seam prominently in the lego catalog — it applies to every boolean prop on every `.ts` lego consumed from `.astro` — and/or give the Lit legos an explicit property-only contract for booleans.
- 2026-08-17 — **`handoff:all` is not wired into the ship path it is documented as belonging to**: `gen-handoff.mjs`'s own header calls `npm run handoff:all` "the deploy path", but `deploy` is `astro build && gh-pages` and `predeploy` is `check-guidance.mjs`, which only CHECKS for manifests and never generates them. Since `public/handoff/**` manifests are gitignored per-machine, `npm run deploy` fails the guidance gate on any fresh checkout until someone knows to run `handoff:all` by hand — and /ship's documented sequence (sync → hub gate → save → build → quick check → deploy) does not include that step. Bit on BCN-1412: the per-section handoff docs, which are the artifact an epic actually references, did not exist until generated manually four days after the prototype was "done". Proposed fix: add `handoff:changed` to the /ship sequence between Build and Deploy, or make `predeploy` generate rather than merely verify.
- 2026-08-17 — **RECURRENCE: composition-heft heuristic still fires on section components** (logged 2026-07-15; proposed fix "apply the heuristic only to files under `src/pages/`" has not landed). Fired on five `bcn-*` section components this branch (`BcnComponentHeader` 127 style lines, `BcnLogoPicker` 159, `BcnWorkAreaBoard` 155, `BcnComponentDataPanel` 206, `BcnSetupWorkspace` 530) — all of which legitimately own their CSS under the manifest discipline's own rules. At 5 of 12 files in scope the signal is pure noise, which is how a real finding gets missed.
